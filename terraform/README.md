# AWS infrastructure (Terraform)

```
Internet
  |-- :80   --> frontend EC2 (public subnet)  --:3000--> backend EC2 (private subnet) --:5432--> RDS PostgreSQL (isolated DB subnets)
  |-- :1883 --> ingest EC2: Mosquitto + mqtt-ingest (public subnet) ------------------:5432--> RDS
  |-- :8080 (your IP only) --> Jenkins controller (public subnet) --SSH--> Jenkins agent (private subnet)

Git push -> Jenkins (polls Git) -> agent builds images -> ECR -> AWS SSM runs /opt/coldchain/deploy.sh on each server -> server pulls the new image
```

## What gets created
| Area | Resources |
|---|---|
| Network | VPC, 2 public + 2 private + 2 database subnets over 2 AZs, internet gateway, one NAT gateway, 3 route tables (the DB one has no internet route), S3 gateway endpoint, DB network ACL, VPC flow logs to CloudWatch, locked-down default security group, private DNS zone (`backend.coldchain.internal`) |
| Security groups | One per role. The backend only accepts port 3000 from the frontend. RDS only accepts 5432 from backend, ingest and the Jenkins agent. Jenkins UI only from `admin_cidrs`. Outbound is limited to HTTPS (plus 5432 and 3000 where needed) |
| ECR | 3 repositories (backend, frontend, mqtt-ingest) with scan on push, encryption and keep-last-10 cleanup |
| Compute | EC2 for backend, frontend, ingest; Jenkins controller; Jenkins agent. IMDSv2 only, encrypted disks, no SSH keys or open SSH ports (use SSM Session Manager) |
| Data | RDS PostgreSQL 16, encrypted, private, password generated by AWS and kept in Secrets Manager; MQTT passwords in Secrets Manager |
| IAM | App servers can pull only their own image and read only their own secrets. The Jenkins agent can push to the 3 repos, run the deploy script on exactly those 3 servers, and read the DB secret. The controller has no AWS permissions beyond Session Manager |

## Deploy
```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars    # set admin_cidrs to your IP, e.g. ["203.0.113.10/32"]
terraform init
terraform plan
terraform apply
```
Wait about 10 minutes (RDS is slow), then `terraform output`.

## One-time Jenkins setup
1. Get the unlock password through Session Manager (no SSH needed):
   `aws ssm start-session --target $(terraform output -raw jenkins_controller_instance_id)`, then `sudo cat /var/lib/jenkins/secrets/initialAdminPassword`.
2. Open `terraform output jenkins_url`, unlock, install the suggested plugins plus **SSH Build Agents**, and create your admin user.
3. Add a credential: Manage Jenkins > Credentials > Global > Add > *SSH Username with private key*. ID `agent-key`, username `jenkins`, key from `terraform output -raw jenkins_agent_private_key`.
4. Add the agent: Manage Jenkins > Nodes > New node. Remote root directory `/home/jenkins`, label `docker`, launch method *SSH*, host = `terraform output -raw jenkins_agent_private_ip`, credential `agent-key`, host key verification *Non verifying* (the agent is only reachable from the controller).
5. Create a job: New Item > Pipeline > *Pipeline script from SCM* > Git > your repo URL (add credentials if it is private) > script path `Jenkinsfile`.
6. Run it once. After that, Jenkins checks Git every 2 minutes and deploys new commits.

The repo you give Jenkins must contain the project root (`Jenkinsfile`, `backend/`, `frontend/`, `mqtt-ingest/`, `database/`). The `terraform/` folder can live in the same repo.

## After the first successful pipeline run
- Dashboard: `terraform output dashboard_url`.
- ESP32 firmware: `MQTT_HOST` = `terraform output -raw mqtt_host`, `MQTT_USER` = `esp32`, `MQTT_PASS` = `terraform output -raw mqtt_esp32_password`.
- Servers are first created with no image, so their first deploy fails harmlessly until the pipeline pushes one.

## Webhook instead of polling (optional)
Set `webhook_cidrs` to GitHub's hook IP ranges (https://api.github.com/meta), add a webhook to `http://<jenkins-ip>:8080/github-webhook/`, install the GitHub plugin, and remove `pollSCM` from the `Jenkinsfile`.

## Known limits and hardening for real production use
- Jenkins and the dashboard use plain HTTP, and MQTT is unencrypted on 1883. Add an ALB with an ACM certificate for the dashboard and Jenkins, and TLS (8883) for MQTT.
- Single NAT gateway, single-AZ RDS and one server per role. Use one NAT per AZ, `multi_az = true` and an autoscaling group for availability.
- The apps connect to RDS as the master user, and the connection skips certificate verification (`sslmode=no-verify`, still encrypted). Create a limited app user and add the RDS CA bundle.
- The Jenkins controller is not backed up. Snapshot `/var/lib/jenkins` or use AWS Backup.
- Terraform state holds generated secrets. Use the encrypted S3 backend shown in `versions.tf`.
- Rollback: re-run the pipeline on an older commit. Images are kept as tags per commit (last 10).
- Cost: the NAT gateway, RDS, and four EC2 instances run around the clock. Run `terraform destroy` when you are done.
